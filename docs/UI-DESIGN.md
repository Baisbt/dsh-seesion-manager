> 配套可视图（`design/` 目录，均为 2× 渲染的 PNG）：
> - `preview-a.png` —— 布局 A：工作区树 + 会话列表（推荐默认）
> - `preview-b.png` —— 布局 B：单栏分组列表（窄宽度更稳）
> - `preview-c.png` —— 布局 C：紧凑表格（数据密度优先，可作为「表格」视图）
> - `preview-states.png` —— 交互状态：侧栏菜单增量、永久删除确认、批量更新标题

## 1. 三种布局与取舍

| | A 工作区树 + 列表 | B 单栏分组 | C 紧凑表格 |
| --- | --- | --- | --- |
| 结构 | 左树（工作区→会话，可折叠）+ 右侧当前范围的会话列表 | 单列，工作区作吸顶分组头，会话行挂在下面 | 全宽表格，工作区分组行穿插，列可排序 |
| 保留文件树 | ★★★ 直接可见目录层级 | ★★ 分组头即目录，可整体折叠 | ★ 目录只在分组行出现 |
| 扫描效率 | ★★ 左右两区各司其职 | ★★★ 单轴向下读 | ★★★ 一屏最多的行 |
| 批量操作 | 树可勾选整棵子树 | 分组头可全选该组 | 表头全选 + 分组头全选 |
| 窄窗口（< 980px 中栏） | 树挤压列表，需要折叠树 | ★★★ 不收宽度税 | 列变挤，需要列设置 |
| 适用 | 默认 | 窗口窄 / 只用鼠标滚动 | 会话上百、要按列比大小与时间 |

**建议**：把 A 做成默认视图，C 作为页头「树 + 列表 / 表格」切换的第二视图（图 A 页头已留了这个切换控件），B 不单独实现，而是 A 在中栏宽度不足时的自适应形态（树折叠成顶部选择器 + 单栏分组列表）。

## 2. 页面骨架

```
┌ 页头 ────────────────────────────────────────────────┐
│ 会话管理                        [搜索] [视图切换] [刷新] │
│ 6 个工作区 · 86 个会话 · 775 MB · 15 已归档 · 1 隐藏      │
├ 筛选栏 ──────────────────────────────────────────────┤
│ (全部 86) (正常 71) (已归档 15) │ (包含已隐藏)  [排序▾]  │
├ 主体 ────────────────────────────────────────────────┤
│ 左：工作区树 322px          右：会话列表（1fr）           │
├ 批量栏（有选择时出现）────────────────────────────────┤
│ 已选择 2 个会话 · 5.4 MB │ 更新标题 归档 永久删除  取消    │
└──────────────────────────────────────────────────────┘
```

- 页头标题 19px/600，副行 12px `--dsw-alias-label-caption`；数字用 `font-variant-numeric: tabular-nums`，避免刷新时跳动。
- 分隔用 `--dsw-alias-border-l1`（6% 白），卡片/行悬停用 `--dsw-alias-interactive-bg-hover`（8% 白），选中行用 9% 的主题蓝（`--dsw-alias-state-business-primary` = `rgb(122,170,255)`）而不是白，让「选中」区别于「悬停」。
- 圆角遵循宿主阶梯：行 8px、卡片/面板 12px、对话框 16px。

## 4. 交互规格

**树**
- 单击工作区节点＝选中该范围（右侧列表只显示该子树）**并且**把这棵子树折叠/展开一次；再点一次就折回去。整行都是点击目标，`caret` 只是状态指示，不再是独立的点击区（也带 `aria-expanded`）。
- 会话叶子（工作区展开后的那一行）：单击＝在右侧列表里定位并高亮该行（不跳转），**双击＝跳到该会话对话**。
- 工作区节点右侧只显示占用大小，不再显示会话数。
- 树页头右上角只有**一个**按钮：当前有展开的子树时显示「折叠全部」，全部折叠时显示「展开全部」——它永远给出与现状相反的那一步，不会出现点了没反应的死按钮。折叠状态按工作区 id 持久化，重开页面保持。
- 树节点勾选框＝批量选择整棵子树（子项显示为半选态）。
- 「已隐藏」独立分组在树底部，默认折叠，右侧有「恢复显示」文本按钮。

**列表 / 表格**
- 选择模型：单击行＝切换该行勾选（再点一次取消，焦点环同时消失，其它已勾选行不受影响）；行首勾选框＝只切换该行；方向键只移动焦点环、不改勾选；空格＝切换焦点行勾选。**打开会话只有两条路：行尾「打开」按钮，或键盘 Enter** —— 双击行不做任何事。
- 列宽：每列固定像素，**紧挨「操作」左边的那一列**（默认「状态」）吃掉剩余宽度并居中内容 —— 表格永远填满面板、不留死空档，「状态」的右边缘就是「操作」的左边缘。该列与「操作」列都没有拖拽手柄（拖不动就不给手柄）。
- 拖动列边界**只改这条边界左右两列**：左边加多少右边就减多少，总量不变，第三列一动不动；右邻居撞到自己的下限就停，绝不溢出。「状态」列是弹性列，由布局自动让位，不需要额外记宽度。
- 列下限：会话列 160px（再窄标题只能竖排），其余列按表头文字算；读到低于下限的旧配置会被抬回下限。
- 列设置面板底部有「按字段名分配宽度」：可用宽度按各字段名的视觉长度（中文 2、拉丁 1）比例分配，每列保底，差额由弹性列吸收。
- 会话单元格：标题最多 **3 行**，第 3 行放不下打省略号，悬停看全文；第二行「时间 · 编号」固定单行 —— 编号先让位，时间永不换行。
- 原生控件（下拉展开层、滚动条）跟随宿主主题声明配色方案，深色页面上不会弹出白底下拉。
- 表头：鼠标进入表头容器即显示**所有**列分隔线（1px，落在 10px 间隔正中，16px 高），正在拖的那条边界换强调色；分隔线只出现在「数据列 ⇄ 数据列」之间 —— 「操作」列不画线，改用底纹（表头 + 整列）区分，读作一条操作轨。
- 行悬停才显示的危险动作永远是图标而非实心按钮，避免误触；点击后走确认。
- 排序：点可排序列的表头（会话→标题、创建、最后活动、大小）即按该列排序，再点一次翻转方向；当前排序列表头显示 ↑/↓，工具栏下拉与升降序按钮和表头共用同一份状态（默认「最后活动·降序」）。
- 搜索：标题、工作区路径、会话 ID 前缀三路匹配；输入即筛，命中片段在标题与工作区名上用 `<mark>`（30% 主题蓝底）标出。
- 筛选：状态 chip（全部/正常/已归档，数字随其它筛选联动）+ 时间范围（不限/近 7 天/近 30 天）+ 大小区间（不限/小于 1 MB/1–100 MB/大于 100 MB）+「包含已隐藏工作区」开关；大小未知的会话在任何大小区间下都会被排除。
- 刷新：按钮重新向宿主**测量**（请求带 `refresh: true`，绕过宿主 30 秒缓存），完成后 toast 汇报条数；大小列悬停显示「日志 x · 投影缓存 y」拆分。
- 空结果：保留筛选栏，列表区给「没有匹配的会话 + 清除筛选」，不是空白（清除会一并复位时间、大小与隐藏开关）。

**批量**
- 选中 > 0 时页面底部浮出批量栏（不遮挡最后一行：列表 padding-bottom 增加 64px）。
- 批量动作：更新标题、归档、取消归档、永久删除；批量栏右侧固定「取消选择」。
- 批量执行时按钮进入 loading 并禁止重复提交，完成后用 toast 汇报成功/失败条数（失败项可展开）。

## 5. 危险操作（永久删除）

设计约束来自「不可恢复」这一事实：

1. 入口是行内 `⋯` 与批量栏里的**红色**文字项，不放在主按钮位置；
2. 弹窗标题直接写清对象与数量（「永久删除 2 个会话？」），正文第一句说明后果（从磁盘删除、不可恢复、不进归档/回收站）；
3. 列出将被删除的会话（标题 + 大小），超过 5 条显示前 5 条 + 「等 N 个」；
4. 必须勾选「我已备份需要保留的内容」才能点亮红色主按钮；
5. 批量 > 10 个时追加输入会话数量确认（防脚本化误操作）；
6. 运行中的会话在列表里带「运行中」状态，弹窗额外警告会中断，并在执行时先停后删。
7. **「打开中」的行不给删**：宿主把会话的 Agent 与日志写入句柄留到进程退出、又没有关闭接口，删文件必然失败。状态列显示「打开中」（空心蓝，与实心的「运行中」区分），行内删除按钮、`⋯` 菜单项与批量删除同时禁用，提示「重启 DSH 后才能删除」；确认流程本身不再作为兜底入口（万一漏网，宿主返回 `session-live`，toast 用本地化文案解释）。
7. **删完要把会话列表拉回来**：宿主只为「打开 / 关闭 / 归档」这类动作推送事件，删文件不会产生任何帧，而侧栏、工作区树与本页共用同一份客户端会话列表 —— 不重拉的话被删的行会「搬」到「未分组」继续显示。所以确认删除成功后立刻调用 `sessions.refresh()`；「刷新」按钮也顺带做同一件事，用于在别处删掉文件后让列表归位。

## 6. 工作区「隐藏」模型

隐藏是本插件引入的概念，必须把语义讲清楚（图上已经用文案写明）：

- **隐藏 ≠ 删除**：图标、会话归属、磁盘目录、`workspace.json` 注册项都不动；被隐藏的工作区从侧栏导航与本页默认列表移除，会话仍可在「包含已隐藏工作区」筛选下看到。
- 入口两处：侧栏工作区 `⋯` → 「隐藏工作区」；本页工作区 `⋯` → 同上。
- 恢复：本页树底部「已隐藏 (n)」分组 → 「恢复显示」；侧栏菜单里对未显示项不出现该条目。
- 「删除工作区」保持 DSH 原行为（会话移交未分类），文案不改，避免用户以为隐藏会删数据。
- **同路径已存在工作区时合并、不重建**：恢复前宿主用 `resolveByPath` 查这条路径；若已有工作区，`create` 会复用它，所以恢复前必须问一次 —— 宿主返回 `needsConfirm`（含目标工作区与会话数），页面弹「合并到现有工作区？」确认后才挂会话 + 取消归档。隐藏分组里这类记录标「将合并」；批量恢复只弹一次确认，不冲突的记录直接恢复。
- **新建工作区不被插件拦截**：用户在原生侧栏添加同路径目录时插件没有介入点，宿主按规范化路径去重，因此不会出现两个同路径注册项；旧隐藏记录从此相当于一张"合并票"，恢复即并入。
- **新增工作区就地提示合并**（`shell.overlay`）：插件订阅客户端工作区快照，发现「没见过的 workspaceId」且其路径命中某条隐藏记录时，在窗口右下角浮出合并卡片（路径 + 工作区名 + 会话数，按钮「合并」/「暂不」）。「合并」＝对该记录发 `confirmMerge` 恢复并删掉记录；「暂不」只是把卡片收掉，记录保留在管理页里。因为宿主的创建动作无法拦截，卡片出现在**工作区创建之后**；自己恢复时产生的那个新工作区用 15 秒的路径抑制避免自我提示。

## 7. 批量更新标题

对应官方「随对话更新的标题」插件的能力，做成一次性动作而不是常驻开关：

- 单条：行 `⋯` → 「更新标题」；批量：选中后批量栏 → 「更新标题」。
- 逐条独立：每行一个状态（生成中… / 已完成 / 失败·重试），一条失败不影响其它条，进度条按完成数推进。
- 幂等与安全：默认不覆盖用户手动改过的标题（设置里可放开）；空会话/无用户消息直接跳过并标「跳过」。
- 成本提示：首次使用在批量栏右侧提示「将为每个会话调用一次模型」，避免误以为免费。

## 8. 侧栏菜单增量（`preview-states.png` ①②）

在宿主已有菜单上**只追加**，不改原有项顺序与图标：

- 会话行 `⋯`：在「归档会话」之后加一条红色「删除会话…」（新增）。
- 工作区 `⋯`：在「删除工作区」之前加「隐藏工作区」与「清理 30 天前的归档」（新增）。
- 追加项统一带「新增」徽标只在设计稿里，落地时不显示徽标。
- 菜单项行为复用同一套服务函数（页面与侧栏共用），避免两套逻辑。

## 9. 其余状态

| 状态 | 处理 |
| --- | --- |
| 首次加载 | 骨架屏：树 3 行、列表 6 行灰块（`--dsw-alias-bg-skeleton`） |
| 扫描大小中 | 大小列显示 `—` 并带轻量 spinner，不阻塞行渲染 |
| 读取失败 | 列表区错误块 + 「重试」，页头统计显示 `—` |
| 无任何会话 | 空状态：一句说明 + 「回到会话」（切回 conversation 面板） |
| 只读/无权限 | 危险动作与勾选框禁用并在 tooltip 说明原因 |
| 会话被外部删除 | 行淡出移除，批量栏计数同步，toast 提示 |

## 10. 无障碍与主题

- 树用 `role="treeitem"` + `aria-expanded`；列表勾选框用真实 `input[type=checkbox]`。
- 批量栏出现时用 `aria-live="polite"` 播报选择数量变化（不是每次点击都播报）。
- 全部颜色走 `--dsw-alias-*`，浅色主题自动跟随；状态色不单独写死十六进制。
- 键盘：`↑/↓` 移动、`Space` 勾选、`Enter` 打开、`Delete` 触发删除确认（需二次确认）。
