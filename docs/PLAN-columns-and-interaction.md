## 1. 列宽：固定总宽 + 内部自适应

### 现在的实现与它的问题

现在是「每列固定 px + 操作列前一条弹性空隙」。拖动任一列变宽时，所有固定列宽度之和会超过容器，最后一条弹性空隙被压到 0，操作列随即被顶出可视区 → 就是你看到的横向溢出。

### 方案 A（推荐）邻列借宽，总宽恒等于容器宽

结构：

```
22px │ 会话 minmax(会话最小宽, 1fr) │ 工作区 px │ 创建 px │ 最后活动 px │ 大小 px │ 状态 px │ 操作 76px
```

规则：

1. **总宽永远等于容器宽**（会话列是唯一的 `1fr`，吸收所有剩余空间）。
2. 拖动某列右边界：
   - 若是「会话」列（1fr）：改变它右侧相邻列的宽度（反向），视觉上就是边界跟着鼠标走；
   - 若是固定列：`w[i] += dx` 且 `w[i+1] -= dx`，两列互借，总宽不变。
3. **夹紧**：被压缩的一列不得低于 `minFor(该列表头文字)`（中文 12px/字 + 拉丁 6.6px/字 + 24px）。到极限就停住，不再移动。
4. **隐藏列**：释放的宽度自动给会话列（`1fr` 天然吃掉）。
5. **兜底**：当所有列都顶到最小宽、容器仍然放不下时，才出现横向滚动（见下一条：表头随行滚动，操作列 sticky 右贴边）。

优点：永不顶出去；"内部列宽自适应"就是字面实现。
代价：调宽某列会轻微影响它右侧那一列（这是表格 splitter 的常规行为）。

### 方案 B 全部按比例缩放

每列存一个权重，`grid-template-columns` 用 `minmax(min, w fr)`，浏览器按权重分配剩余空间；拖动改权重。

- 优点：所有列都"自适应"，没有固定列。
- 缺点：拖一列会**牵动所有列**，用户很难建立"我改的是这一列"的心智模型；最小宽叠加后同样可能溢出。

### 方案 C 固定像素 + 横向滚动

每列纯 px，超出就滚动。

- 优点：最简单、完全可预测。
- 缺点：**正是你现在不满意的那种"顶出去"**，只应作为 A 的溢出兜底，不建议作为主模型。

> **拍板 #1**：A / B / C？（建议 A）

### 与"固定总宽"配套的必要改动

要保证"总宽不溢出"，表头和数据行必须共享**同一个横向滚动容器**，否则一旦触发滚动，表头会与数据错位。具体做法：把 `thead + rows` 包进一个 `overflow-x: auto` 的容器，表头 `position: sticky; top: 0`，操作列 `position: sticky; right: 0` 并且列本身不参与压缩。

> **拍板 #2**：接受"表头与行共用横向滚动容器（仅溢出时生效）"吗？（建议接受）

### 其他细节

- 窗口变窄：会话列先被压到最小，再窄才滚动。
- 双击表头边界 = 该列自适应内容宽度：默认**不做**（容易误触），可后续加。
- 列宽/列序/可见性继续持久化在 `localStorage`，键与结构不变。

## 2. 侧栏「永久删除」补红色垃圾桶图标

已核实的菜单契约：

```ts
interface MenuAction { id, label, icon?: { key: string, src?: string }, danger?: boolean, separatorBefore?: boolean, run?() }
// 渲染：icon → renderSlot('contextMenu.icon', { icon }, { entryKey: icon.key })   // keyed 插槽
```

### 方案（推荐）

1. 注册 `contextMenu.icon` 这个 keyed 插槽的一个 occupant，`key = 'dsh-session-manager.trash'`，渲染我们自己的垃圾桶 SVG，**描边用 `currentColor`**。
2. 菜单项保持 `danger: true` → 宿主把整行（含图标槽位）染成错误色 → 图标自然变红，**不写死色值**，浅色主题也正确。

### 兜底

若该插槽对第三方 key 不生效（只认内置图标表），则改用 `icon.src` 传 data-URI SVG，并把 `--dsw-alias-state-error-primary` 的颜色烘进去（缺点：切主题不会自动跟随）。

### 顺带调整

当前我们的项排在「归档会话」**之前**，与设计稿（危险项永远最后）不符：改为 `order` 放到归档之后，并加 `separatorBefore: true`。

## 3. 行点击 = 选中，不跳转

现在的实现把两个概念混成了一个集合：`selection` 既是"批量勾选"又是"点了哪一行"，而点击行会直接 `openSession`。

### 新状态模型（两个独立状态）

| 状态 | 含义 | 谁改它 | 视觉 |
|---|---|---|---|
| `activeId` | 焦点行（单选） | 单击行、↑/↓、树定位、侧栏菜单定位 | 强调描边（accent 40%）+ 更深底色 |
| `checked: Set` | 批量勾选 | 勾选框、表头全选、Shift 连选 | 淡蓝底（现有样式） |

两者可叠加：焦点行同时被勾选时，两种样式都成立（描边最外层）。

### 交互

- **单击行任意空白处** → 只设 `activeId`，不改勾选、不跳转。
- **单击勾选框** → 切换该行勾选（不改变焦点）。
- **双击行** → 打开会话。
- **Enter** → 打开当前焦点行。
- **Space** → 切换焦点行勾选；**↑/↓** 移动焦点；**Shift+↑/↓** 扩展勾选区间。
- 行内「打开」按钮保留（现在的第一个图标）。
- 右键菜单不变。

### 打开会话的触发方式（需要你选）

| 方式 | 是否保留 |
|---|---|
| 行内「打开」按钮 | 建议保留（已有） |
| 双击行 | 建议**新增** |
| Enter 键 | 建议**新增** |
| 单击行标题文字 | 建议**取消**（与"单击=选中"冲突） |

> **拍板 #4**：双击 + Enter + 按钮三者都开？（建议是；如果你只要按钮，删除会很慢）

## 5. 树点击 = 聚焦右侧并闪烁，不跳转

现在点树里的会话叶子会直接 `openSession`（跳走）。

### 新行为

1. **定位**：若该会话在当前列表视图里可见 → 直接滚动；若被 scope/搜索挡住 → 见下方选项。
2. `scrollIntoView({ block: 'nearest', behavior: 'smooth' })`（只滚到"刚好可见"，不把行顶到最上）。
3. 设 `activeId` = 该行。
4. **闪烁**：600ms 一次性脉冲（背景从 accent 12% 淡到 0，仅 1 次），`prefers-reduced-motion: reduce` 时改为静态选中、不闪。
5. 不打开会话、不切换主面板。

### 被筛选挡住时怎么办（需要你选）

| 选项 | 行为 |
|---|---|
| a（建议） | 只切 scope 到该会话所属工作区；若仍不可见（搜索词挡着），清空搜索 |
| b | 一律切到「全部会话」并清空搜索，最大概率定位成功 |
| c | 什么都不改，只提示"该会话被当前筛选隐藏" |

> **拍板 #6**：a / b / c？

### 保持不变的行为

- 点工作区节点 → 过滤右侧列表（不是跳转）。
- 点顶部「全部会话」→ 过滤。
- 侧栏菜单「永久删除」→ 仍会切到本页（否则看不到确认框），但改为"先定位再弹框"。

## 7. 风险提示

- 第 3 条会改变肌肉记忆：原来"点一下就进会话"，之后需要双击或 Enter。这是你要的（选中优先），但值得在行的悬停提示里保留"双击打开"的暗示。
- 第 1 条方案 A 的"邻列借宽"会让相邻列一起动；如果你更希望"改哪列就只动哪列、总宽可溢出"，那就得选 C（接受横向滚动）。
- 第 5 条与第 3 条共用 `activeId`，实现上是一次改动，不会互相打架。

## 执行结果（2026-11-14，已落地）

按"全部推荐 + 表体一律左对齐"实施，与方案的差异记录如下：

1. **列宽**：落地为"**slack 优先、再用邻列借宽**"——拖动时先吃掉操作列前的弹性空隙，空隙耗尽后才从右邻列借宽，两者都受"表头文字宽度"下限约束；因此**总宽恒等于容器宽，操作列永不被顶出**。因为不再可能溢出，方案里的"共享横向滚动容器"就不需要了（少一层 DOM 结构）。测量容器宽用 `.dsm-list` 的 `clientWidth`（拖拽开始时读一次）。
2. **表头居中 + 表体左对齐**：`.dsm-th` 改为 `justify-content: center`；`大小` 列去掉了右对齐，表体全部左对齐（按你的修正，替代方案里的 a 选项）。数字仍保留 `tabular-nums` 等宽数字。
3. **侧栏删除图标**：注册了 `contextMenu.icon` 的 keyed occupant（key `dsh-session-manager.trash`），描边 `currentColor`；菜单项 `danger: true` → 图标继承错误色。**顺序**：DSH 把「归档会话」固定在菜单末尾（`afterContent`），所以我们的项只能排在它之前；已加 `separatorBefore` 用分隔线隔开，语义上仍是"危险项单独一块"。
4. **行点击 = 选中**：新增 `activeId`（焦点行）与 `checked`（批量勾选）两个独立状态。单击行只设焦点并画 1px 强调描边；打开会话改为**双击 / Enter / 操作列第一个按钮**；行标题不再可点，title 提示"双击打开"。
5. **树点击 = 定位 + 闪烁**：树叶子改为"切 scope（必要时清搜索）→ 滚动到该行 → 设焦点 → 600ms 呼吸一次"；`prefers-reduced-motion` 下不闪只选中。
6. **键盘**：列表获得焦点后 ↑/↓ 移动焦点行、Enter 打开、Space 切换勾选（Shift 连选未做，留待下一轮）。
7. 附带修复：行选择样式与勾选样式可叠加区分（描边 vs 淡蓝底）。
