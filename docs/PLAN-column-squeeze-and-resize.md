# 方案与执行：会话列挤压 · 列宽拖动规则 · 下拉配色

> 状态：**已落地并验证**（2026-11-15）。全部在 Client 半（`client.js`），不涉及 Host。
> 你拍板的三点：会话列下限 **160px**、自动分配**纯按公式**、下拉**先做方案 A**。

## 1. 会话列被拖窄后竖排堆字

**现象**：会话列窄到 70px 左右时，标题被拆成一两个字一行，时间被拆成"21 / 分 / 钟 / 前"。

**原因**：每列能拖多窄，只按**表头文字**算 —— "会话"两个字算出来是 56px。
可这一格装的是两行内容（标题 + 时间·编号），56px 完全不够；标题原本是"单行不折"，一旦窄过头，
时间和编号这两个横排元素就各自被压成竖排。

**改动**：

| 项 | 处理 |
| --- | --- |
| 会话列下限 | 160px（`COLUMN_MIN_WIDTH`）。拖不动，且**旧配置里低于 160 的宽度在加载时被抬回 160**，所以你现在这张截图里的窄列刷新后自动复原 |
| 标题 | 最多 **3 行**，第 3 行放不下打省略号；`title` 属性仍是全文，悬停即见 |
| 第二行 | 固定单行不折：时间与分隔点不可压缩，**编号先让位**（省略号），时间永不换行 |
| 对齐 | 会话格改为填满列宽（原来是居中收缩），这样折行宽度等于真实列宽，不是内容宽度 |

代价：标题占满 3 行时行高约为原来的 2.2 倍，一屏条数变少；默认 320px 下绝大多数标题仍只占 1 行。

## 2. 拖动列宽只影响左右两列 + 按字段名分配

**原现象**：往右拖"工作区"的边界，先被吃掉的是最右边"状态"列的多余空白 —— 看起来第三列被牵连。

**新规则**：这条边界左右两列**一增一减**，总量不变，其它列一动不动。
右邻居是"状态"列时它由布局自动让位（本来就算"剩余宽度"），不需要额外记宽度。
右邻居撞到自己下限时，左边那列**停在原地**（不再溢出、不再牵连第三列）。

**按字段名分配宽度**（列设置面板底部新增按钮，纯按你给的公式）：

- 可用宽度 = 面板宽 − 勾选框栏 − 列间距 − 内边距（`ROW_INSET` = 34）。
- 每列份额 = 可用宽度 × 该字段名的视觉长度 ÷ 全部字段名视觉长度之和（中文 1 字 = 2，拉丁 1 字母 = 1）。
- 每列再套下限（会话 160，其余按表头文字），不足的补到下限，多退少补的差额全部丢给弹性列，保证表格仍然正好填满。
- 举例（当前 7 列，字段名单位合计 17，可用宽度取 1000）：会话 118→**160**、工作区 176、创建 118、最后活动 235、大小 118、状态 118、操作 118；多出来的 42 从「状态」那份里扣。

副作用你已知：字段名最短的会话列恰好内容最长，所以纯公式下它会偏窄，靠 160 兜底。

## 3. 下拉展开层是浅色

**原因**：`<select>` 展开的那一层由浏览器/系统自绘，只认页面声明的 `color-scheme`；我们没声明，默认按浅色画。

**改动（方案 A）**：启动时读一次宿主页面底色亮度，判断深/浅，把配色方案声明到页面根节点上 ——
系统弹层与滚动条随之变深色。另外给候选行加了兜底的深色底/浅色字，个别忽略该声明的构建也能看。

判断逻辑：先看 `body`/根元素的实际背景色（半透明则跳过），都拿不到时用文字颜色的明暗反推；取不到就当深色。
若某台机器上的系统弹层仍是浅色（Windows/显卡组合偶发），再上方案 B：自绘弹层，复用右键菜单那套样式。
